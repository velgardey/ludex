# Data ownership and retention

The local development server stores journal records, command receipts, public projections and hashed opaque-session tokens in the configured SQLite file. Passwords use scrypt with per-account random salts. No password, session bearer token or OIDC signature is written to application logs. The database is private development data and must stay out of Git. Local SQLite is not an encrypted cloud backup service; restrict filesystem permissions and use host disk encryption.

Progress is private unless the individual command explicitly selects another audience. Directed follows expose public content only. Accepted friendships and owner-managed circles govern restricted content. Blocks deny social access both ways. The server constructs the viewer; supplying a user ID in a URL grants no access. Spoiler-restricted text is absent from JSON. Hidden-title projections also replace the title ID, artwork, title name and provider bindings.

Account export is schema version 1 and contains the owner's account, private journal/commands/drafts/settings and their authored social records. It excludes credential hashes, bearer sessions and third-party private records. Downloads require the current authenticated owner and expire after 15 minutes. Expired snapshots are unavailable and removed on download; re-export replaces previous snapshots, and the Functions publication timer cleans expired snapshots. Its deployed lifecycle remains unverified.

Deletion first disables the account in the social partition and changes the policy revision. That immediately denies existing sessions, feed/showcase access and replies, before asynchronous cleanup. The local process queues immediate cleanup; Functions includes a five-minute deletion worker. Cleanup is repeatable and removes the private partition, credentials, sessions, authored activity/showcase/collections, relationships and reactions. The deletion tombstone and closed owner-partition write guard remain so a restore can reapply deletion and stale requests cannot recreate journal records. Moderation/audit records need an explicit operational retention decision and anonymization before external launch.

The intended cloud policy is a 24-hour live deletion target with encrypted disaster backups retained at most 7 days and deletions replayed before restored data is served. This policy is a release requirement: no cloud backup, restore drill or provider retention was verified here. User uploads, metadata stripping, caps, 24-hour raw-upload expiry and blob deletion are not implemented in Stage A local API; the UI must not offer an upload as operational.
