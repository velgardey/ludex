# Stage A backend report

Date: 2026-10-06. Workspace: managed `ludex-stage-a` worktree. Scope: shared domain/contracts/client, local API, cloud adapters/wrappers, backend operational docs. This report records local backend evidence; it does not mark Stage A release accepted.

## Delivered behavior

`@ludex/domain` carries the specification's shared types plus catalog, account/session, library runs, showcase/collection and projected activity types. Pure reductions preserve watched/skipped TV sets and rewatches, separate game story/milestone/time/achievement state, retain original platform versus played device/emulator, enforce optional integer 1–10 ratings and require every spoiler prerequisite. `@ludex/contracts` uses Zod to validate HTTP commands, dates, text lengths, media-specific changes, audience and settings. Date day/month precision stays explicit.

`@ludex/client` exports `LudexClient`, shared types and `LudexError`. Default base is `http://localhost:4000/api`; native emulator uses `http://10.0.2.2:4000/api`. The client attaches bearer tokens and binds browser fetch to its global receiver. The real local credential path uses invited signup, scrypt salts/hashes, opaque 256-bit sessions stored by hash, seven-day expiration and logout revocation. New real accounts have empty libraries/feed/showcases. Sample preview uses invented people/activity separately and cannot be logged into.

`node apps/api/src/server.ts` serves the persistent loopback SQLite API. `LUDEX_DB_PATH` controls storage, default `.local/ludex.sqlite`. SQLite WAL, prepared statements, scope checks, transaction rollback and ETag compare enforce the repository contract. Progress atomically writes event, owner projection, receipt and eligible publication outbox in one owner partition; receipt retries keep exactly one event/version and changed payloads reject. Library edits version-check and never infer watched episodes from a completed-state edit. Corrections append evidence, replace the affected active assertion, recompute progress and immediately deny retracted events during serialization. Publication uses stable activity IDs, current event/account checks and a separate social transaction; no cross-partition atomicity is claimed.

The API includes bounded feed pagination with signed viewer/filter/policy-bound cursors; follows, friendship request/accept/remove, owner circles requiring accepted friends, current privacy checks, reviews/drafts and edit/retract, replies/edit, reactions, showcase/collections, user discovery/status, settings, block/report, role-checked moderation queue/remove/suspend, authenticated expiring export and immediate account disable with repeatable asynchronous cleanup. Spoiler notes/labels are omitted from JSON. A hidden-title projection removes title name, artwork and provider identifiers and substitutes `hidden` for identifying title fields. Parent activity access governs replies/reactions. Public users expose no email or credential data. All HTTP responses use `no-store` and explicit-origin CORS; local request body and per-process rate caps are implemented.

Eight canonical UUID preview titles include films, shows with explicit episode IDs/order and games including the original Nintendo 64 Ocarina of Time edition. Preview demonstrates six covers, a spread shelf and a hidden-game activity. Cached titles support real manual logs. Seed artwork is provider-hosted preview material, not a licensed production integration. Controller verified current TMDB Severance/Past Lives source paths; this worker verified Disco Elysium/Hades header URLs returned HTTP 200 image/jpeg on 2026-10-06. That evidence establishes URL availability only.

## Cloud scaffold and release limits

The Cosmos SDK adapter implements read/list and single-partition transactional batch with ETag conditions. The Functions v4 wrapper supplies HTTP, publication and deletion timers, requires OIDC and Cosmos settings, and never falls back to local passwords. Operator-only OIDC invitation provisioning reserves a maximum cohort slot atomically and does not accept client roles. `infra/main.bicep` compiles and creates no resources with default `cosmosFreeTierEligible=false`; all billable resources are gated. The candidate template uses one region, Cosmos provisioned 400 RU/s and `/scope`, LRS backing storage and Consumption Y1 Functions. The compiled Node 22 candidate and region/SKU must be checked before deployment.

No cloud deployment, signed Android device, real External ID redirect, provider catalog credential/license, FCM, avatar/upload handling, cloud backup/restore, live load/cost meter or paid model call was performed. Stage A release remains open. TMDB/IGDB live adapters, real notification delivery and session grouping are absent. Local auth has no refresh/password reset/MFA/mail mechanism and is explicitly disallowed in production. Device PKCE/login must use External ID after tenant setup. Provider observations currently ingest only as quiet private exact mappings; Stage B consent/integrations are not implemented.

Cloud queries currently scan the bounded cohort's partition documents before filtering and projection. Output pagination is bounded, but RU/latency/read volume is not established and requires query optimization/load measurement. Rate limits are per process, not distributed quotas. Exhaustive failure injection at every publication interruption/ETag race, provider rollback, moderation retention/anonymization, uploads/type/dimension/metadata caps, restored deletion replay and operational alerting remain release gates. The intended 24-hour deletion/7-day backup policy is documented, not verified against Azure storage. Exports keep one active snapshot; expired downloads remove it and the Functions timer cleans expired snapshots. This cloud timer has not been deployed. A US$10 monthly service limit remains a quote-and-measure target; underlying spend and credits have not been inspected.

## Decisions and integration

The controller owns root workspace/configuration, web/mobile integration and commits. This worker did not commit. Local native TypeScript tests use Node 26 rather than Vitest; that uses the actual supported `node:sqlite` seam. Cloud runs compiled JavaScript and excludes the SQLite server. No public API accepts arbitrary role/subject bindings. The local default invite exists solely to let the actual two-account manual loop run; production requires a verified invited OIDC subject. Root lint deliberately ignores API/shared packages, so a scoped backend ESLint configuration and zero-warning invocation cover these sources.

Primary integration review should assess repository transactions, current ACL checks, hidden projections and product release limitations before merge. The backend author self-reviewed, and controller dispatched a fresh scoped reviewer after integration; its findings are handled before completion.

## Fresh review fixes

The controller's scoped fresh review found four material issues, each addressed with local regression coverage: nonempty spoiler prerequisites and scope/title/media/catalog binding on progress/reviews/replies; a durable `write-guard` retained in each deleted user partition, compared by ETag in every private mutation, with social mutations guarded by current account ETag and a queued job retained when guard closure conflicts; cleanup conflicts leave deletion queued instead of falsely done; concurrent identical correction retries return the committed receipt; and exports keep a single active snapshot with expired-read removal plus a Functions cleanup timer. A controlled paused private transaction resumed after deletion cannot recreate records and returns conflict. The retained closed guard is deletion metadata, not journal content. Generated-JWKS/local tests establish these rules; cloud races and restore reapplication remain a release gate.
