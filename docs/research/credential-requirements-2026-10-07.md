# Ludex beta credential requirements

**Research date:** 7 October 2026
**Status:** Provider documentation review only. No provider credentials were read, provisioned, or tested; no live API, OAuth callback, quota, deployment, or cost was verified. This is a checklist for the Android beta (about 100 users; roughly US$10/month target), not an environment file. Supabase Auth is excluded by the product decision; direct Google OAuth is selected, with its exact Android flow still to be finalized.

## Credential checklist

| Beta capability | Credential/config needed | Scope and handling |
|---|---|---|
| **Azure chat** | Backend resource endpoint, server API key (or configured Entra identity), and deployment name. The chosen label is `gpt-6-luna`; confirm that deployment exists and supports the selected API in the target resource before runtime. | One Ludex-level credential, server only. Microsoft’s Responses API requires a deployed model and API key or Entra authentication. Chat does not supply embeddings: provision a separate embedding deployment only if a later feature actually needs vectors. [Responses API](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/responses?view=foundry-classic), [embeddings](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/embeddings?view=foundry-classic) |
| **Supabase Postgres + Prisma** | Database connection string for runtime; separate direct connection string for Prisma migrations if the chosen hosting topology uses Supavisor pooling. | Ludex backend only. Keep both server-side. Because Supabase Auth is not used, do not add Supabase Auth URL/key values solely for login; Prisma connects directly to Postgres. [Prisma + Supabase connection guidance](https://www.prisma.io/docs/orm/overview/databases/supabase) |
| **Direct Google sign-in** | Google OAuth client registration, callback URLs, package name and signing-certificate SHA-1. The Android client ID is public app configuration; a Web client secret, if using Google’s server-side web-app flow, stays on the backend. The backend also needs a Ludex-generated session-signing secret or opaque-session mechanism. | Google user credentials stay with Google; do not collect passwords. Request only `openid email profile` for sign-in; if no Google APIs are called, keep the Google subject and required profile fields, discard provider tokens after validation, and issue a Ludex session. Google documents native installed-app OAuth as system-browser + PKCE with a public client, while its web-server flow uses a confidential client secret and registered HTTPS callback. These are distinct app types: select one end-to-end flow and verify it before putting both clients in runtime config. Verify state, nonce, ID-token issuer/audience/expiry, one-time callback handling, and a Ludex-owned session. [Native OAuth/PKCE](https://developers.google.com/identity/protocols/oauth2/native-app), [web-server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [OpenID Connect state/nonce and ID-token checks](https://developers.google.com/identity/openid-connect/openid-connect), [Android signing SHA-1](https://developers.google.com/android/guides/client-auth) |
| **TMDB film/TV catalog** | One application API key or API Read Access Token. | Global Ludex read credential, backend only. No viewer OAuth is needed for catalog search. Only add per-user TMDB auth if Ludex later reads or writes a user’s TMDB lists. Check attribution and commercial-use terms before launch. [Application authentication](https://developer.themoviedb.org/docs/authentication-application), [user authentication](https://developer.themoviedb.org/docs/authentication-user), [API terms](https://www.themoviedb.org/api-terms-of-use) |
| **Twitch/IGDB game catalog** | Twitch Developer application Client ID and Client Secret; backend mints an app access token using client credentials and sends the Client ID plus Bearer token to IGDB. | One global app credential/token, backend only; no user Twitch login for public catalog lookup. IGDB says noncommercial use is free under its agreement and directs commercial projects to partnership; confirm beta/launch fit and terms. [IGDB authentication and use](https://api-docs.igdb.com/), [Twitch app registration](https://dev.twitch.tv/docs/authentication/register-app), [Twitch OAuth](https://dev.twitch.tv/docs/authentication) |
| **Steam library/achievements** | One standard Steam Web API user key registered for Ludex; a user links their Steam identity through Steam OpenID, yielding their SteamID. | Steam key is a global backend secret; SteamID is per-user data, not a secret. OpenID proves identity but does not override Steam privacy settings. Owned-game and achievement results depend on visibility. Never collect a Steam password or use a publisher key as a consumer sync credential. [Key setup](https://partner.steamgames.com/doc/webapi_overview/auth), [owned games](https://partner.steamgames.com/doc/webapi/IPlayerService), [OpenID](https://partner.steamgames.com/doc/features/auth), [Steam API terms](https://steamcommunity.com/dev/apiterms) |
| **Trakt account import** | Trakt app Client ID; each user separately authorizes via OAuth Authorization Code + PKCE. Store that user’s access/refresh token securely on the backend if ongoing sync is enabled. | App ID is global; tokens are per-user. Client Secret is deprecated for user sign-in in current docs; use PKCE. Ask only for the API permissions required to import that user’s own history. Confirm app registration, policy, access eligibility, any fee, and current quotas before beta; this review does not settle Trakt pricing or grant access. [Create app](https://developer.trakt.tv/docs/create-an-app), [OAuth](https://developer.trakt.tv/docs/authentication-oauth), [PKCE](https://developer.trakt.tv/docs/pkce), [API-use policy](https://developer.trakt.tv/docs/api-use-policy), [rate limits](https://developer.trakt.tv/docs/rate-limiting) |
| **Letterboxd history** | No API credential for beta: user uploads their Letterboxd export ZIP/CSV. Generic CSV also needs no provider credential; it is user-supplied data. | The official export supports a user-initiated one-time import. Do not make Letterboxd API access a dependency: it is request-only and Letterboxd currently excludes personal/private projects and data-analysis, visualization, recommendation, or LLM/GPT use cases from access grants. [Export data](https://letterboxd.com/user/exportdata/), [API access policy](https://letterboxd.com/api-beta/access/) |
| **Netflix desktop quick capture** | No Netflix API key, OAuth, or Ludex handling of a Netflix password. A Chrome/Edge extension needs declared Netflix host access and a user action; optional page detection is permissioned, best-effort observation of the visible site. | No supported public consumer playback API is established by the reviewed sources. Do not market this as playback sync or use Netflix account credentials. Chrome host permissions and content scripts are browser permissions, not provider credentials. [Chrome host permissions](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions), [content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts), [Netflix viewing activity](https://help.netflix.com/en/node/101917) |
| **RetroAchievements (optional)** | Each user supplies their RA username and their own Web API key if they opt into the connector. | Per-user secret; encrypt server-side, redact outbound request URLs because the documented key is sent as a query parameter, allow disconnect/rotation, and never ask for the RA password. This is key-based access, not OAuth. Keep the connector optional; the documented Web API is polling-oriented. [Getting started](https://api-docs.retroachievements.org/getting-started.html), [user summary](https://api-docs.retroachievements.org/v1/get-user-summary.html) |
| **Android push (only if included)** | Firebase Android app config (`google-services.json`, package/project identifiers) and server-side authorization for FCM HTTP v1, preferably workload identity/ADC or a protected service-account credential. | The Android config file contains app identifiers and is not a server credential. Sending credentials remain on the backend. No iOS Firebase artifacts are needed for Android-only beta. [Android FCM setup](https://firebase.google.com/docs/cloud-messaging/android/get-started), [FCM sender authorization](https://firebase.google.com/docs/cloud-messaging/send/v1-api#authorize-http-v1-send-requests) |

## Keep out of the first beta credential set

Plex, Jellyfin, AniList, MyAnimeList, and Watchmode are later candidates; none is required by the selected beta scope. Do not create their app keys now. Console connectors are outside the accepted beta scope; do not provision console-platform credentials for launch. Netflix CSV history, if offered, is a separate one-time user import and needs no Netflix API access.

## Missing inputs before templates or launch

- Confirm the exact Google OAuth client flow: native Android client + PKCE, or a backend web client + HTTPS callback. Google’s docs separate these client types; the Android package name, debug/release/Play signing SHA-1 fingerprints, public client ID, redirect domain, and app-link scheme must be known. If the beta relies on Google’s test-mode audience, confirm current tester eligibility and publication requirements.
- Confirm Azure resource, endpoint, API auth method, and actual `gpt-6-luna` deployment availability. Price the selected deployment and place product-side request/token limits before promising a US$10 ceiling.
- Obtain production owner-managed API credentials and verify current rights, quotas, and terms for TMDB, IGDB/Twitch, Steam, and Trakt. Provider access, price, and registration are not proven by these docs.
- Decide whether push notifications are in the beta; if yes, create the Android Firebase app and sender identity. Confirm whether RetroAchievements is enabled for launch; otherwise omit its per-user credential flow.

A 100-person beta does not multiply global app keys, but it does affect user-token storage, rate use, and API/model cost. This research made no live credential or endpoint calls and establishes neither a working login nor a monthly price.
