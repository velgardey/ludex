# Progress sync feasibility for Ludex

Date: 2026-10-06
Status: source review; no provider integration or authenticated runtime test has been performed.

Deeper review: [integration-depth-2026-10-06.md](integration-depth-2026-10-06.md) refines Steam presence/achievement chronology, supported players, regional links and Xbox access. Xbox has documented official authentication and achievement endpoints; independent consumer-app production access remains unverified. The initial grouped console assessment below should be read with that correction.

This report checks what public, first-party documentation supports for importing entertainment progress into Ludex. A documented API is evidence of a possible integration path, not proof that Ludex has credentials, provider approval, production quota, or a working connector. “No public API found” means none was found in the official sources reviewed; it does not establish that no private or partner API exists.

## Catalog metadata is a separate integration

Progress sources and title catalogs solve different problems. Ludex still needs canonical movie, show, episode, game, and edition records to match imported events safely.

- **TMDB** documents movie, TV, season, and episode APIs with API-key/Bearer authentication. Its terms require attribution for non-commercial use; commercial use requires a separate license. Confirm the applicable license and artwork requirements before a commercial launch. [Getting started](https://developer.themoviedb.org/docs/getting-started), [FAQ and attribution](https://developer.themoviedb.org/docs/faq), [commercial terms](https://www.themoviedb.org/api-terms-of-use?language=en-CA)
- **IGDB** uses Twitch application credentials and client-credentials tokens for game metadata/search. Its docs describe free use as non-commercial and direct commercial projects to partnership. The API documentation reviewed did not expose player achievement/progress data. Confirm a commercial agreement before depending on it. [IGDB API documentation](https://api-docs.igdb.com/)

Metadata attribution or API access does not grant rights to copy or redistribute user progress from a separate provider. Keep provider ID mappings and user events distinct.

## What the source review supports

**Documented behavior:** Steam offers visibility-dependent snapshots and game-published achievements; Trakt offers user-authorized reads and client-submitted scrobbles; Plex documents configurable webhooks; Jellyfin exposes server session/playback mechanisms; Netflix and Letterboxd support user-facing history/export paths; the reviewed direct-to-consumer streaming and console sources do not document a general public consumer progress feed.

**Inference for product behavior:** Plex webhooks and Jellyfin session messages may feel close to live when Ludex can receive them, but neither documentation set provides a Ludex delivery SLA. Steam and Trakt reads will be stale between polls. CSV imports are historical snapshots. A mobile app cannot infer other apps’ playback or arbitrary console game events just because the user has signed into Ludex.

**Not verified at runtime:** No OAuth flow, webhook, polling job, network callback, account permission, provider quota, title mapping, refresh token, or console integration has been exercised for Ludex. Production credentials, approval, legal terms, and user-level access need separate validation. No API absence statement here rules out private partner access.

## Recommended launch sequence

1. **Make Ludex progress canonical.** Manual logging should update the library immediately and work for every title. Keep viewing runs, watched episode IDs, game playthroughs, and user-recorded milestones; do not reduce every medium to one percentage. A private library update and a published friend-feed event are separate decisions.
2. **Start with explicit import and a review queue.** Provide CSV import where user exports exist (notably Letterboxd and Netflix if its current export is usable), match against the canonical catalog, show uncertain matches, and suppress historical imports from live feed/notifications by default.
3. **Validate a movie/TV connector before committing to it.** Trakt is the broadest documented user-authorized route in this review, subject to app access and policy review. Plex is a compelling push-style option for users with a Plex Pass and a reachable callback. Do not ingest friends’ Trakt data to construct Ludex activity. Select the first connector only after checking credentials, commercial/policy terms, quotas, rate limits, corrections, and a real test account.
4. **Add Steam as opt-in polling.** Import only what the user’s privacy settings expose. Display source and last-sync time; distinguish an observed achievement from Ludex-verified completion. Never infer a boss event that the game did not publish.
5. **Keep Jellyfin as an advanced, opt-in connector.** Scope access narrowly, disclose when admin privileges are required for broader session visibility, protect credentials, and verify self-hosted reachability. A local companion may help some deployments but is a separate product and security project.
6. **Keep streaming-service and console progress manual for now.** Offer “log this episode/game milestone” as the fast, universal path. Revisit integrations only with documented public access or a confirmed partner agreement. Browser automation or extensions would be a separate, brittle, explicitly permissioned path and do not solve console telemetry.

## Product contract for freshness and trust

For every connector, show what data it can read, its last successful sync, whether updates are pushed or polled, and whether the event is provider-reported, inferred from a snapshot, or entered by the user. Give users per-source disconnect, delete/import-history, visibility, and correction controls. Deduplicate retries using provider event IDs where available; for snapshots, compare against a stored checkpoint and treat the first sync as history. Never turn an imported observation into a public activity until the user’s Ludex sharing and spoiler settings allow it.

The truthful launch promise is: **automatic updates where a supported source exposes them, and a fast log action everywhere else.** Provider freshness is outside Ludex’s own low-latency budget; internal feed delivery can be fast after Ludex receives and accepts an event.
