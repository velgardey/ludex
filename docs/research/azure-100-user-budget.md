# Ludex Azure budget feasibility for a 100-user beta

**Research date:** 6 October 2026
**Scope:** Official Microsoft Azure pricing and documentation only. No Azure subscription, portal resources, or model deployment were inspected or created.

## Verdict

A private beta with 100 registered users can be designed to have very low Azure infrastructure charges by keeping the website static, using one region, choosing an eligible free database and identity offer, and avoiding paid always-on services. That does **not** establish that the complete product will cost less than US$10 every month. Azure model inference is pay-per-token, the public pricing page did not expose numeric GPT-4.1-nano rates in this research, and Azure budget alerts are not a billing stop. Metadata rights or fees, domains, Google Play account costs, tax, and any third-party services also sit outside this Azure-only estimate.

The credible beta promise is therefore **“designed for a US$10 monthly Azure target, with product-enforced AI limits and an immediate non-generative fallback”**, pending a region-specific Azure calculator quote and actual usage measurements. It is not yet safe to promise an unconditional hard cap while allowing unlimited conversational AI.

## Cost follows activity, not registrations

“100 users” is not enough to predict spend. Fixed or provisioned resources bill while configured, Functions bill for their billable executions and active memory, databases have their own compute or provisioned-throughput meters, and AI bills from the tokens sent and returned. Concurrency matters separately for services that meter simultaneous connections.

Microsoft Entra External ID’s core offer is free for the first 50,000 monthly active users, so 100 registered users fit that user-count allowance. Some premium add-ons have no free tier, and SMS authentication incurs a separate per-attempt charge. Prefer email or social sign-in and exclude paid identity add-ons from the initial cost target. [External ID pricing](https://azure.microsoft.com/en-us/pricing/details/microsoft-entra-external-id/), [External ID pricing model](https://learn.microsoft.com/en-us/entra/external-id/external-identities-pricing)

## AI spend scenarios

Azure’s current public Azure OpenAI pricing page lists GPT-4.1-nano across Global, Data Zone, and Regional deployment choices. In the Microsoft page fetched on 6 October 2026, the input, cached-input, and output price fields appeared as `$-`; therefore this report does not invent a dollar-per-token rate. Confirm the exact model version, deployment type, Azure region, and USD rate in the signed-in Azure Pricing Calculator or selected deployment before committing a monthly quota. Pay-as-you-go uses input and output token meters; cached inputs may have their own rate. [Azure OpenAI pricing](https://azure.microsoft.com/en-us/pricing/details/azure-openai/)

Let `Pi` be the quoted USD price per million uncached input tokens and `Po` the quoted USD price per million output tokens for the chosen model and deployment. For each answer, count the user prompt, system instructions, conversation history, and retrieved library/profile/feed context as input. Count the complete billed model output, including reasoning tokens when the selected model exposes and bills them, as output.

| Usage pattern | Monthly answers | Assumed input per answer | Assumed output per answer | Monthly token totals | AI cost formula |
|---|---:|---:|---:|---:|---:|
| 100 registered users, 20 short replies each | 2,000 | 1,200 | 250 | 2.4M input; 0.5M output | `2.4 × Pi + 0.5 × Po` |
| 20 daily active users, 10 replies/day each for 30 days | 6,000 | 1,500 | 500 | 9M input; 3M output | `9 × Pi + 3 × Po` |
| 100 daily active users, 10 replies/day each for 30 days | 30,000 | 1,500 | 500 | 45M input; 15M output | `45 × Pi + 15 × Po` |

These are workload examples, not Azure quotes. They assume ten completed assistant answers per daily active user per day in the “extended chat” case. More history, retrieval, longer outputs, retries, tool calls, or another model raise the token total. With one fifth of the daily active users, token cost is one fifth at the same per-user pattern. The 100-daily-user pattern has 18.75 times the input tokens and 30 times the output tokens of the 100-registered-user short-reply pattern; the table shows 45M versus 2.4M input and 15M versus 0.5M output. Each individual paid model call must be counted, even when multiple calls produce one displayed assistant reply.

For an actual US$10 target, first reserve the measured monthly non-AI Azure bill, then calculate the remaining AI allowance. If `B` is the remaining AI dollars, `Tin` and `Tout` are average input and output tokens per answer, the rough maximum answer count is:

```text
max_answers = floor(B × 1,000,000 / (Tin × Pi + Tout × Po))
```

Do not promise unlimited chat from a token formula. Keep the conversational companion central, but gate cloud model calls with per-user and shared monthly token/request quotas, short context windows, strict output limits, and no automatic multi-step retries. When a quota is reached, retain catalog search, personal library lookup, shortlist creation, and logging assistance as fast structured flows; explain that generative replies resume at reset or when the beta operator raises the cap. Make every generated write a user-confirmed action. Measure tokens from real requests before raising limits.

## Budget controls and hidden bills

Azure Cost Management budgets produce actual/forecast notifications and can invoke action groups, but a budget is a spending target, not a synchronous spending cap. A person or automation may react after usage has accrued. Use both an Azure alert and a product-side AI ledger that reserves the maximum allowed tokens before making a model request; monitor provider usage and turn off model calls in the app when the product cap is reached. Never rely on a budget alert alone to keep a US$10 ceiling. [Cost Management overview](https://learn.microsoft.com/en-us/azure/cost-management-billing/costs/overview-cost-management), [budget alert tutorial](https://learn.microsoft.com/en-us/azure/cost-management-billing/costs/tutorial-acm-create-budgets)

Other costs to include when quoting the pilot include Function backing-storage transactions, any user-uploaded avatars or media in Blob Storage, internet egress above applicable allowances, paid SMS, multi-region replicas, telemetry ingestion beyond grants, and a dynamically rendered Next.js server. Keep posters and video out of the app’s storage; use catalog-provided image URLs only within that provider’s license and hotlink rules. This review did not price catalog metadata or image providers, the app-store account, domain registration, tax, or support. Those could invalidate an all-in US$10 promise even if Azure infrastructure remains inside the target.

## Decision boundary for the beta

The US$10 ambition is plausible only as a **strictly metered beta**, not as an open-ended AI companion plus global low-latency infrastructure. The low-cost shape is one backend region, static companion pages, one eligible free database offer, core External ID sign-in, on-demand functions, structured retrieval, no dedicated AI Search, no always-ready compute, and polling in place of an always-on realtime service. Start with 100 registered users, measure daily active users and simultaneous connections, and limit cloud generative answers to a quote-backed allowance. Revisit the cap after one measured billing period.

Prices and free-program availability can vary with region, agreement, currency, and subscription eligibility. Free grants do not cover third-party costs and may stop serving or pause a resource when exhausted. Azure trial credits are temporary and should not be counted as sustainable monthly budget.

## User decisions after this research

The user accepted existing Azure credits/deployments as possible subsidies, capped short assistant conversations with a structured fallback, a single region with measured refresh, and 100 invited accounts with roughly 10–20 simultaneous users. Build/operation will be through Codex; no deadline was provided. This does not establish the balance, expiry or eligibility of credits or the marginal price of an existing model deployment. Track actual resource cost separately from credit-adjusted cash paid; revisit the US$10 target when credits expire or deployment billing changes. The initial connector choice is Steam plus a browser extension; Trakt is selected for a dedicated historical importer; continuous Trakt sync is a later candidate.
